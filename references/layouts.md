# 版式参考，不是页面清单

这里的页型是从实际提案里提炼出来的**结构样本**，用来启发构图，不是必须逐页套用的模板，也不覆盖全部表达需求。

## 怎么用

1. 先按 `composition.md` 写视觉转译表，确定这一页要让观众看懂什么关系。
2. 关系与下表接近时，再打开对应骨架，看它的结构能否直接承载；不能就改，或另画。
3. 颜色、字号、圆角、线条全部来自当前模板 token。版式只决定位置、对齐、分组和阅读顺序。
4. 大纲里的关系不在下表时，**自建版式**。不要为了用现成页型而改变内容关系，也不要把段落硬塞进三栏或流程框。
5. 同一份演示不要求每页都用不同页型，但相邻页避免同一构图；一页只保留一个主构图。

版式 CSS 由构建器统一注入（`runtime/layouts.css`，在模板 CSS 之前），不需要复制进模板。需要为单次内容调整时，把相关规则复制到内容工程覆盖，不改共享文件。

## 参考页型

| 页型 | 适合表达 | 骨架 | 不适合 |
|---|---|---|---|
| 泳道 `flow` | 几处触点、角色或工具并列，共用同一套数据或规则 | `layouts/flow.html` | 有明确先后顺序（用管线）或需要逐项对比（用矩阵） |
| 管线 `pipeline` | 有先后顺序的步骤，以及每步的明细、产出 | `layouts/pipeline.html` | 循环、分叉或多条路径并存 |
| 矩阵 `matrix` | 多个方案按同一组问题逐项对比，其中一列是建议项 | `layouts/matrix.html` | 只有两个对象且差异简单；对比维度彼此无关 |
| 双轨 `tracks` | 两条路径并行推进，需要突出其中一条 | `layouts/tracks.html` | 两条路径有先后依赖或会互相分流 |
| 阶梯 `ladder` | 信息逐层收窄、逐层提炼，越往上越少 | `layouts/ladder.html` | 宽度或层数需要对应真实数量时（这里不表示比例） |
| 双路验证 `paths` | 两条并行验证路径，底部有共同前置或共同关卡 | `layouts/paths.html` | 两条路径互斥只能选一条；或只是普通并列清单 |
| 来源与范围 `sources` | 左侧输入清单，右侧研究或工作范围分组 | `layouts/sources.html` | 输入与范围存在一一对应关系（需要连线时另画） |

封面不在此库：封面主视觉从本次主题提取，由模板的封面规范和内容共同决定。

## 结构要点

### 泳道 `flow`

- 上排并列 2–4 个触点，每个触点包含：场景标签、动作、说明、一条示意记录。
- 底部一条共享底座，写明这些触点共同依赖的东西。没有共享底座时，用普通并列卡片即可，不必套本页型。
- 箭头只表示「数据流向同一处」，不表示因果或自动执行。

### 管线 `pipeline`

- 上方一排步骤名，可带编号；下方用 2–3 张卡片展开角色、环节或注意事项。
- 步骤数可以增减，但超过 6 段时先考虑拆页。
- 底部可放两个衡量指标；没有真实数据时不要画刻度或进度。

### 矩阵 `matrix`

- 行是同一组问题，列是方案；单元格用短词、符号或一句判断，不放长段落。
- 只高亮一列。高亮表示推荐或讨论重点，不表示已选定。
- 维度不一致时先合并维度，不要为了凑满表格编造对比项。

### 双轨 `tracks`

- 每条轨道 3–4 个节点，节点之间用箭头表示推进顺序。
- 用 `is-accent` 强调其中一条；强调的是讨论重点，不是优劣结论。
- 两条轨道节点数不同时，保持同一视觉节奏，不强行补齐。

### 阶梯 `ladder`

- 左侧放现场原始材料，右侧放逐层提炼后的层级。
- 只表达「范围逐层收窄」，宽度不代表数据比例；需要比例时改用条形图。
- 最上层可高亮一个最终结论；没有结论时留空，不编造。

### 双路验证 `paths`

- 两条路径各自列出 2–4 步，步骤编号对齐。
- 底部一条共同关卡，写清两边共用的前置条件或通过标准。
- 只写计划时，明确「这是验证计划，不代表已执行」。

### 来源与范围 `sources`

- 左侧列输入，每项标明类型、数量（如有）和用途；右侧按主题分组列范围。
- 两侧是「看了什么」与「准备解决什么」，不是一一映射；不要把分组硬画成连线。
- 数量必须是真实可核对的；示例数量要标明虚构。

## 改造与自建

- 改列数、改段数、增删节点、换强调位置都可以；复制骨架到内容目录后再改，不改 `runtime/layouts.css` 去适配单次内容。
- 自建版式直接用普通 HTML 加模板 token（如 `var(--surface)`、`var(--accent-text)`），不必新增 `ly-` 类名。
- 只有确认会被多个项目复用的结构，才考虑沉淀回本库；一次性的特殊构图留在内容工程。
- 任何版式都不能改变已确认的标题、数字、页序或业务含义；结构服务内容，不反过来。

## 预览

```sh
python3 scripts/build.py --manifest layouts/deck.json --out output/layouts.html
python3 scripts/build.py --manifest layouts/deck.json --design designs/deepleaper-dark/design.md --out output/layouts-brand.html
```

示例内容全部虚构，仅用于展示结构。构建后仍要按 `SKILL.md` 的验收步骤逐页看真实渲染。
