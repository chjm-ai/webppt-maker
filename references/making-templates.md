# 模板：一个目录，一份完整规范

模板是一个自包含目录，不引用别的模板：

```
designs/<slug>/          公共模板，随 Git 分发
  design.md              规则 + 全部 tokens
  layouts.css            视觉骨架
  assets/                品牌素材
data/templates/<slug>/   私有模板，不进 Git，结构相同
```

**每个模板都写全自己的规则和 tokens，共用内容也复制一份。** 多几十行文字，换来的是改任何模板都不会牵连别人，也不用记“哪些该写、哪些不该写”。

## 新建：复制一个现成的再改

```sh
cp -r designs/d-dark designs/acme-dark
```

然后改三处：

1. `design.md` 的 JSON：`name` 改成目录名；改需要变的 token。
2. `design.md` 的文字：改标题和描述；有品牌 Logo 就加一条 Logo 用法。
3. `assets/`：换成自己的素材。

私有模板同理，复制到 `data/templates/`，不依赖 `designs/`。

## 两种改动程度

| 要改什么 | 怎么做 |
|---|---|
| 只换颜色、字体、间距、Logo | 改 tokens 和 assets；`layouts.css` 通常不动 |
| 换版式骨架（分栏、标题位置、背景结构） | 改 `layouts.css`；tokens 跟着调 |

判据：**页面上元素的位置关系要不要变**。不变就只改 tokens。

换浅色要额外改两处，容易漏：`layouts.css` 开头的 `color-scheme: dark` 改成 `light`；`texture-ink` 从白色半透明改成深色半透明，否则纹理在浅底上看不见。

## 规则怎么写

`design.md` 必须包含五节：固定项、默认可调、自由项、素材、可执行配置。

- 固定项：任何页面都不能违反的（颜色用途、分割线政策、Logo 留白）。
- 默认可调：可按内容微调的数值，写清默认值和调节变量。
- 自由项：交给内容决定的部分（构图、图表、卡片数量）。
- 素材：模板目录里有哪些文件、怎么用。
- 可执行配置：JSON，构建器读取。

品牌条款直接写进固定项（如“正文右上用字标，宽 `13.5cqw`”），不要写“与某某模板的差异”——那份模板以后可能被改，差异描述会过时。

## 校验

保存后立刻运行，**报错就不要宣称模板已保存成功**：

```sh
python3 scripts/check_templates.py                          # 全部模板
python3 scripts/check_templates.py --template designs/acme-dark
```

脚本会拦这些错误：JSON 读不出／`name` 与目录名不一致／tokens 为空／token 名或值不合法／`layouts.css` 用到但 tokens 没定义／对比度不达标／还写着已废弃的 `extends`／公共模板被 Git 忽略／公共页面引用了 `data/templates/` 私有素材／私有模板文件已被 Git 跟踪／示例 deck 指向不存在的模板或页面。

它会提示这些提醒：私有模板没写「固定项」等三层结构。

构建时也会跑同一套 token 检查：即使忘了校验，缺变量会在构建直接报错，不会带着空值出稿。

## 选用

- 用户指定模板名／品牌：从 `designs/*/` 与 `data/templates/*/` 的目录名匹配；只列目录名，不默认加载全部素材。重名、无匹配、一个品牌对应多个模板时询问，不猜、不静默退回默认。
- 未指定：列出实际可用模板供选择，并提供“不使用模板”；不在叙事大纲阶段先问配色。
- 用户要求查看或理解某个模板时，先 `check_templates.py --template` 确认结构完整，再读取规范与素材。
- 已有成品小改沿用其当前模板。

## 三层约束

| 层次 | 保存什么 | 制作时如何处理 |
|---|---|---|
| 固定项 | 颜色用途、字体家族与层级关系、Logo 原貌与留白、封面／正文纹理分区、标题区对齐、分割线政策 | 全稿共用；用户本次明确要求才能覆盖 |
| 默认值 | 字号／行距、边距、标题区高度、纹理强度、色块比例 | 先用 tokens；长标题、截图、密集图表可按内容微调，记在 plan.md；不能每页另起风格 |
| 自由项 | 主视觉、构图、图表、卡片数量、图片位置；新拟大纲是否需要副标题 | 按内容关系决定；已确认的页数、副标题与页面分工不可擅改 |

同一套风格应能支持流程、关系、证据、对比、强文字等构图。可用基础 CSS 的 `.slide-title`、`.slide-subtitle`、`.brand`、`.surface`、`.texture-card`、`.brand-fill`、`.accent-surface` 等视觉角色，也可用等效命名；换类名不等于实现规范。

## 使用素材与构建

1. 读取模板 `design.md` 和必要的 CSS、素材；按素材清单选正确版本，不猜文件名、不重绘 Logo。
2. 图片直接写文件名（如 `src="monogram-blue.png"`），构建器依次在**内容目录**和**模板 `assets/`** 中查找，并内嵌为离线资源，不必复制副本。Logo 不拉伸，裁空白不裁图形。
3. 在 `plan.md` 记录模板路径、固定项、调整项、素材用法；扩展构图用项目自己的 CSS，不回写模板。
4. 构建：`python3 scripts/build.py --manifest <内容目录>/deck.json --design <模板目录>/design.md --out <新文件>`。
5. 浏览器验证固定项与内容表达两条线。逐页核对已确认副标题确实上屏，不能只留在讲稿里。品牌素材既查加载，也查比例与视觉角色；封面以品牌符号为主视觉时，不得缩成角落小图标。

### 一份页面，多套模板

随附示例用同一套页面出两套效果，靠页面元素上的标记控制显示：

```html
<div data-template-only="deepleaper-dark">只在该模板出现的 Logo 块</div>
<div data-template-only="!deepleaper-dark">其他模板才出现的替代块</div>
```

构建时按当前模板保留或删除整块元素，输出里不留标记。自建模板要复用示例页面时，用同样方式加分支，不要复制两份页面。

## 新建模板清单

1. **定位置**：获准公开分发的品牌用 `designs/<slug>/`；未获授权的品牌、客户素材用 `data/templates/<slug>/`。slug 用小写英文短横线。
2. **复制底稿**：`cp -r designs/d-dark <目标>`，再把 `design.md` 的 `name` 改成目录名。
3. **改差异**：只改这个模板真正要变的部分；共用部分保持复制来的内容。
4. **放素材**：Logo、字体、图片放 `assets/`，文件名用原名，不重绘、不染色。
5. **跑校验**：`check_templates.py --template <目录>`，错误清零才继续。
6. **出一页样稿**：构建一页真实尺寸页面，浏览器截图确认 Logo、配色、标题区正常。
7. **报告结果**：说明放在哪、从哪个模板复制、校验结果。私有模板要提醒“不进 Git，换机器需手动备份”。

## 从成品提炼

只提炼已经认可的样式；去掉客户标题、真实截图、项目专用类名与逐页绝对坐标。验证时要换成另一套内容／不同构图仍成立，再保存。

## 更新模板

- 先看谁在用这套模板（示例 deck、项目内容），说明影响范围。
- 模板是快照：改一个不会影响另一个。想让其他模板也跟着变，手动同步。
- 单次页面微调不自动回写模板；用户明确说“更新模板”才动。

## 已知失败边界

- 原品牌色适合小色块＋白字，不适合直接做深底小字或细线；按角色使用更亮的辅助色。校验脚本会实算对比度，不改措辞蒙混。
- 封面满幅纹理，正文只在标题区；内容区不铺满，只有强调卡片可按需加纹理，不能每个组件都叠材质。
- 中文封面标题推荐行距约 1.09；不把 1.04 或固定换行强套所有字体。
- 内容页不重复左上项目路径／长页眉；标题上移后仍给右侧 Logo 留宽度。
- 标题组内紧凑、组间留白更明显；不要把页顶和主副标题同时压到极小再在正文前留大段空白。
- 细斜纹在缩放、压缩、投影时可能有摩尔纹；只在浏览器看过不能声称投影通过。
